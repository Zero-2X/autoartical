# 学术研究写作技能

先读取主题目录中的要求、证据台账、选题说明和 `workspace/research/research-brief.json`。不要直接从模糊题目写正文；先把研究对象、证据和可证伪主张固定下来。

## 何时使用

当任务包含文献综述、研究选题、相关工作、研究动机、方法设计、benchmark、baseline、case study、主实验、论文初稿或不少于 40 页的实质正文时使用。只需要改一段已有文字时，使用 `document-writing`，仍需遵守引用和事实边界。

## 固定研究链路

按以下顺序生成或检查 `workspace/research/research-brief.json`：

1. **领域**：给出领域名称、研究价值和影响事实；每个事实绑定来源。
2. **子领域**：给出任务定义、对象、输入输出、边界和选择理由。
3. **挑战**：把通用挑战写成可观察的失败模式，并说明影响、条件和可测后果。
4. **Current methods**：按机制或信息来源分类，不按论文标题堆砌；每类至少记录代表工作、机制、优点、缺点、适用边界和 `evidence_ids`。
5. **缺口**：用“现有缺陷 → 未解决矛盾 → 关键研究问题”闭环，关键问题必须可被实验证伪。
6. **科学设计**：每个组件都写 design、rationale、testable prediction，并指向它要修复的缺陷。
7. **案例**：用真实或明确标注的合成案例展示机制、过程、结果证据和失败边界；不能把案例计划写成已发生结果。
8. **主实验**：冻结 claims、benchmark、baseline、metrics、数据划分、统计口径和成功判据；每个指标说明测量对象及要证明的主张。

运行入口：

```bash
python workflow/scripts/run_research.py ./my-topic
```

研究 brief 通过后仍不能直接视为长文完成。正文写作阶段必须运行 `evaluate_document.py` 的默认长文模式和 `content_depth_gate`；只有研究草案或选题卡可显式使用 `--allow-short`，并且该状态必须保留为短种子，不能进入最终交付。质量审查会同时检查有效正文量、段落密度、重复段落、引用数量和问题—机制—实验—边界四类语义覆盖。

首次运行会生成研究问题、查询计划、证据缺口和研究 brief 骨架。补充来源或由研究代理完成 brief 后再次运行；已有 brief 默认保留，只有明确重置时使用 `--reset`。`research-gate.json` 为 `pass` 后才允许进入文档规划。

## 文献证据规则

- 检索问题、搜索摘要、模型常识和项目假设都不是事实证据。**任何参考文献不得凭记忆写出**（Orchestra ml-paper-writing、K-Dense citation-management 的共同规则）：在 `workspace/evidence/references.json` 中按正文首次引用顺序登记 arXiv 号或 DOI、期望标题、该文献支持的具体主张，以及发表载体和载体依据（如 arXiv comment 中的 “Accepted to CVPR 2018”）和 `venue_year`；运行

  ```bash
  python workflow/scripts/verify_references.py <topic>/workspace/evidence/references.json --out-dir <topic>/workspace/evidence
  ```

  脚本从 arXiv/Crossref 取回元数据，标题不符、载体无依据、无法取回时失败，并生成 GB/T 7714 条目 `references.gbt7714.md` 和核验记录 `citation-verification.json`。
- 正文中的每个数字必须能在被引文献的原文（至少是摘要）中找到；把摘要原文中的数值抄入 `claims` 字段，写正文时只引用这些数值。不同文献的数值来自不同评测协议时，不放在同一张表中比较。
- 把“来源支持的原文主张”和“根据多项来源作出的推断”分开记录；推断必须写明“本文推断”及理由。摘要没有提到的能力写“摘要未提及”，不写“不具备”。
- 检索覆盖要求：奠基性工作、近年代表性成果、强基线、竞争路线和负面证据（反例、评测缺陷、方法失效报告）都要有。按“路线—核心假设—在本领域何处失效”组织，不按论文逐篇罗列（K-Dense literature-review：thematic, not study-by-study）。
- 检索停止条件写进正文：主要方法类别已覆盖、每个研究缺口至少有一篇直接依据、冲突结论已解释、未覆盖方向已列明。
- 使用 PaperQA2、Docling、MarkItDown 等外部工具时，只吸收其检索、解析和定位能力；转换结果必须回到原文核验。

## 写作结构

相关工作每个类别使用“类别定义 → 代表方法 → 共同优势 → 共同局限 → 对本研究的启示”。引言使用“领域机会 → 子领域瓶颈 → 明确研究问题 → 设计回答 → 贡献边界”。方法部分使用“问题约束 → 机制 → 组件 rationale → 算法/接口 → 复杂度和边界”。实验部分使用：

- Q1 主效果：证明方法是否在预先声明的任务上改善主指标。
- Q2 组件验证：证明关键设计是否带来可归因的变化。
- Q3 稳定性与代价：证明鲁棒性、效率、规模或失败边界。
- Q4 案例分析：解释机制如何工作，不能用定性案例替代主实验。

每段至少承担一个信息任务：事实、定义、比较、推导、条件、限制或决策依据。删除后若不损失这些信息，就删掉。禁止用背景套话、同义复述、没有来源的数字和“显著提升”等空结论充正文。

## 交付门禁

进入 `document_plan` 前：研究 Gate 必须通过。正文默认合同为**正文不少于 40 页、不设上限**，前置部分、参考文献与附录分别计数；篇幅从计划阶段按章节重要性分配，方法与实验章节应是最长的部分，末章不得超过正文的 10%。超出 40 页的部分必须是实质论证，标题、表格、图片和重复段落不计入有效正文。

实验章节必须逐项写明：每个实验回答哪个问题、对应哪个假设、用什么数据划分和对照方法、每个指标测量什么及不能说明什么、如何控制预训练语料泄漏/影像重叠/调参泄漏、统计方法（按影像而非候选重采样）、多重比较处理、什么结果会推翻假设、负面结果出现时的停止规则。未运行的实验在表格中写“待实测”，不得生成虚构数值或曲线。

图表与交付门禁见 `document-writing` 与 `doctoral-thesis-format`：示意图走逐图 ImageGen 流程，数据图走 `make_chart.py` 可复现绘制，表格必须有表题、正文引用和写明来源或依据的表注；PDF 由 Word 从 DOCX 导出，自动检查与人工审查分别记录并绑定文件哈希。
