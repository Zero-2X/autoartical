# 实质正文与视觉交付约束（正文不少于 40 页）

正文不少于 40 页是从选题开始就固定的交付合同，不设上限；超过 40 页的部分必须是实质论证。页数口径为正文（第1章至参考文献前），前置部分、参考文献和附录分别计数。先固定正式模板的纸张、页边距、字体、字号、行距和图表尺寸，再进行页数核验。禁止以大字号、异常行距、空白页、强制分页或巨大图片扩页。

视觉合同不再规定 ImageGen 图片数量配额。每幅图必须承担机制、比较、数据、案例或框架之一的论证作用，正文先引用后出现；数据图必须由登记数据可复现绘制；每张表必须有表题、正文引用和写明来源或依据的表注。默认至少 6 幅图，用于防止关键论证完全缺少图示，而不是鼓励凑图。

## 内容预算

默认正文最低 24000、目标 32000 个中文字符与英文单词混合计数单位。这是本项目的起始写作预算，不是通用“字数换页数”公式，也不是完成保证。先按现有章节权重分配，再结合证据和正式版式调整；调整需同步章节预算、总量和理由。超过目标不自动失败，但必须审查冗余。图表本身有价值，保留其必要性审查，但不替代正文最低量。

规划脚本将预算写入 section-plan.json 的 content_contract 和各章节 suggested_word_budget。逐章与全书检查不计标题、表格、代码、公式、图片和重复段落。全书检查仅统计计划中的正文章节。旧项目需重新规划或明确补录内容合同；不能沿用短稿的通过结论。

## 有效扩写方法

每个小节先列“要回答的问题—主张—来源定位—推导／设计—适用边界—与下一节的关系”，再撰写。每一段必须增加可识别的信息，删除后若不损失事实、推理、条件或决策依据，就删除。

| 内容 | 必须增加的信息 | 禁止的替代品 |
|---|---|---|
| 问题与需求 | 对象、场景、约束、失效案例、可测需求 | 宏大背景、重复意义 |
| 相关工作 | 检索范围、方法分类、同条件比较、缺口依据 | 堆砌论文摘要与引用数 |
| 方法 | 输入输出、符号、假设、机制、推导、替代方案取舍 | 只列模块名与流程图 |
| 实现 | 数据模式、接口、关键算法、复杂度、异常处理、部署条件 | 通用技术百科 |
| 验证 | 数据划分、基线公平性、指标定义、实验设置、消融、误差与失败分析 | 编造数值、把计划写成结果 |
| 应用与风险 | 使用流程、成本口径、边界、风险触发条件、缓解措施 | 无依据的市场规模和收益 |
| 结论 | 回答原问题、证据支持程度、局限与待验证项 | 重复摘要、夸大贡献 |

资料不足时先补检索与原文阅读。仍无数据时只能写明确标识的验证方案；如果交付要求实验结果，保持未完成状态。增加字数不能消除证据缺口。

## 审查与交付

1. 撰写者逐节核对问题是否回答充分、事实是否有来源定位、方法是否可复现。
2. 运行 `manuscript_lint.py`（结构、引用、图表编号、元信息、未标注结果数字、碎片与近重复段落、末章占比）和 `content_depth` 篇幅检查。注意：篇幅计量只去除真实 HTML 标签，`p < τ` 一类比较符不会再被误删。
3. 图表按 `document-writing` 的图表规则制作，`build_figure_table_gate` 逐图逐表检查来源与论证作用。
4. `run_document_export.py` 由 Word 生成 DOCX 与 PDF 并做版式自动检查，见 [博士论文式版式契约](doctoral-thesis-format.md)。
5. 人工在全页渲染上逐页审查并分别登记视觉与语义结论（`qa_ledger.py record`）；`qa_ledger.py verify` 重新计算哈希，任何输入或交付文件变化都会使旧记录失效。
6. 篇幅不足回到对应小节补资料、机制或分析；页面稀疏时调整段落与图表的先后顺序，不得缩小字号。

本仓库的 skill 负责从选题、研究、内容、视觉到交付门禁的闭环；需要实际 DOCX/PDF 交付时，使用环境可用的 documents/pdf skill 完成渲染核验。润色不能替代研究，也不以 AIGC 检测分数作为内容质量标准。
