自动研究到底研究什么

Q1–Q2领域与子领域

说明研究对象、任务边界和研究价值，禁止用宏大背景替代任务定义。

Q3挑战与影响

把挑战写成可观察失败模式，说明影响、条件和可测后果。

Q4Current methods

按机制分类，逐类写代表工作、共同优势、共同缺陷和适用范围。

Q5关键缺口

形成“缺陷 → 未解决矛盾 → 可证伪研究问题”的闭环。

Q6科学设计

每个组件都要有 rationale、机制假设和 testable prediction。

Q7案例与主实验

明确 benchmark、baseline、metrics、成功标准，以及每项实验要证明的主张。

入口：python workflow/scripts/run_research.py ./my-topic。首次运行生成 research brief 骨架和检索计划；证据不足时停止，补齐后重跑。

怎样得到好的结果

有效做法

  • 先固定研究问题，再让方法回答问题。
  • 把每个事实绑定到来源和原文位置。
  • 用统一标准比较方法，而不是堆论文摘要。
  • 让实验问题、指标和结论一一对应。
  • 补充机制、边界、失败分析和取舍。
  • 40–50 页由实质正文自然构成。

会导致低质量的做法

  • 把搜索摘要或模型常识当作证据。
  • 先写方法，再倒推研究动机。
  • 只列 benchmark，不说明测量目的。
  • 用表格、图片、留白和重复段落凑页数。
  • 把计划、假设和结果混写。
  • 用关键词命中代替事实核验。

按文档类型调整重点

论文

重点是可检验问题、相关工作分类、方法复现、benchmark 公平性、消融、统计和局限。

竞赛说明书

重点是用户痛点、方案闭环、创新与实现证据、应用流程、风险和展示可理解性。

基金申请书

重点是科学问题、研究目标、技术路线、前期基础、创新点、可行性和风险控制。

仓库中的可复用能力

academic-research-writing

研究型任务的统一 Skill：从领域研究到实验契约，再进入写作。

document-writing

逐章正文、引用、图表、内容密度和全书审查。

source ingestion

PDF/Office/HTML/Markdown 导入，缓存、哈希、页码/行号定位。

research-gate

缺少证据、方法比较或实验协议时阻止正文规划。

content-depth

检查有效正文量、重复段落和 40–50 页内容合同。

render verification

用正式模板核对页数、字体、断页、图表、公式和引用。

研究与写作的边界

GitHub 项目提供了可借鉴的能力形态：PaperQA2 的引用型科学检索、AcademicForge 和 ClaudePrism 的 skill 化工作区、PaperDebugger 的研究—批评—修订闭环，以及 Docling、MarkItDown、Pandoc、Typst 的资料与交付链路。AutoArtical 只吸收公开的工作方法和接口边界，保留自己的证据台账、状态文件和审查规则。

自动化可以生成问题、整理来源和检查结构，不能替人确认事实、编造结果或替代领域判断。
